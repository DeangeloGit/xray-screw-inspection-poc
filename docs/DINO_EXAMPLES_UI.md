# DINO 範例管理

主程式入口：工程設定 → AI 模型 → 展開「DINO 螺絲範例管理」。管理功能直接顯示於工程頁面，使用共用模板和限定於元件內的 CSS／控制鎖定。切換模型後同步工程頁上方模型資訊。

主程式尚未重新載入 API 的既有工作階段，工程頁會內嵌已開啟的本機 18767 範例管理服務；重新啟動主程式後使用同站 API，不依賴額外服務。此相容路徑僅於 localhost/127.0.0.1 且 API 404 時啟用。
網址：`/engineer/dino-examples`。

不重啟既有檢測服務時，可用 `start-dino-examples.cmd` 開啟獨立範例管理頁：
`http://127.0.0.1:18767/engineer/dino-examples`。它與檢測程式使用同一模型資料夾和 windows-check 工作目錄。

1. 選擇要修改的 DINO 版本，分別查看螺絲與非螺絲。
2. 每張並排顯示原圖和實際 AI 輸入；取消勾選，只會從新版本停用。
3. 在對應類別上傳裁好的圖片。伺服器產生實際灰階／縮放／中央取圖預覽，無推論、無寫入模型。
4. 填寫名稱，建立新版。兩類各需 3～500 張；每張最多 8 MB，每次最多新增 100 張，整個請求最多 40 MB。
5. 查看剛建立的版本，確認後才按切換使用。舊版保留，可選回。

建立版本會重用保留範例的原始向量，只對新圖片計算 DINO 向量。新目錄保存模型檔、範例圖片、圖片雜湊、向量與來源版本；完整驗證成功才公開新版本。建立失敗清除自己的暫存目錄，不變更 active.json。模型選擇沿用既有驗證與持久化 API。

舊範例庫原本只有向量。本專案透過 `experiments/dino/seed_example_images.py` 將 31 張螺絲與 65 張非螺絲原圖附加至既有版本的 `examples/` 與 `examples.json`；原 manifest、權重與 active.json 不變。缺少原圖的舊版本會提示，不能假造圖片。

未建立的修改只保留在網頁草稿，重新整理會消失。切換查看版本前會提示放棄草稿。上傳不會改寫原始圖片；新庫不會自動重新檢測歷史照片。

範例更換是否有效，要用未加入範例庫的照片比較，不能用同一張教完再考。此功能不宣稱新版本辨識率一定更高。

驗證：`experiments/dino/verify_examples.py` 在臨時工作目錄測試列圖、實際輸入預覽、非法路徑／圖片／數量、建立失敗回復、新向量一致性、版本保存、明確切換與切回。`experiments/dino/verify.py` 檢查原 114 張小圖結果不變。
