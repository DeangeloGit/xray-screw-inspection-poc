# 5r 外殼範圍與完整物件複核

這次修改處理兩個不同問題：明亮外殼邊緣未被原檢測範圍涵蓋，以及小差分片段被當成獨立螺絲。原模型、範例庫、雙圖規則及受 SHA 驗證的既有複核程式保持不變。原入口 `live5r_local_service.py` 仍可使用；新入口為 `experiments/dino/live5r_spatial_service.py`。

## 處理順序

1. 原 4r 完整偵測及既有 5r 局部複核先完成，保存不可覆寫的基線結果。
2. 從正常參照圖中尋找與機體相連的較淡外殼輪廓。原深色機體遮罩只用作起點；依機體尺度限制搜尋帶，再以實際影像輪廓建立外殼包絡，不把單純膨脹的白底範圍直接當成檢測區。
3. 新通道只追加主要位於原遮罩外、且不與既有候選重複的差分候選。追加候選仍使用原主庫、整合複核、接頭規則及局部複核。原通道候選不重新排序或修改，新增候選不能回頭影響其分類。
4. 對原本保留、最大邊不超過 16 預覽像素的小框，先檢查是否有跨兩個明暗層穩定的緊實核心；有就保護原警報。否則找影像支持的較完整物件，要求較寬的兩種背景範圍都支持鄰近參照結構對應，最後用原主庫重新判斷完整物件。只有參照、待測都不像螺絲才排除，任何條件不足就保留。
5. 排除前再加保守保護：即使核心沒有跨明暗層穩定，只要單一層仍有覆蓋小框至少一半、最大邊不超過 32 像素的物件，就不能確定它是碎片，維持原雙圖警報。核心分類分數仍記錄，但不能用負分推翻這個保護。這是維持原決策，不是新增人工螺絲標籤。
6. 新外殼通道另外檢查細長殘差：若長寬比超過既有核心定義的 3，必須在其中找到跨尺寸穩定、且原雙圖分類支持的螺絲核心才升為警報。候選與原分數仍全部保存。這條規則不碰原通道的警報。
7. 全部既有階段完成後，針對新外殼通道內仍被排除、最大邊不超過 32 像素的小候選，執行穩定物件補救。在 8／12／20 像素周圍範圍各做 Otsu 分割，要求物件框 IoU 至少 0.8、涵蓋至少半個候選、不碰搜尋邊界，且符合最小邊 5、面積 20、長寬比不超過 3 的完整物件條件。先決定幾何，不依分數挑框；再用物件外加 2／4 像素各做原主庫雙圖判斷，兩次皆「待測像螺絲、參照不像螺絲」才追加警報。原保留結果及未救回的排除結果逐項保持不變。

這不是全域調高門檻，也沒有新增或刪除訓練圖。固定螺絲正例保留；線材內真正的圓形螺絲不能因周圍像線而直接刪除。3129、3094 沒有加入特殊座標、檔名規則或假定缺陷答案。

## 檔案與追溯

### 原有結構觀察（2026-11-20）

`structure_shadow5r.py` 已接在全部正式階段之後。它只寫 `structure-shadow.json` 及結果中的 `structure_shadow5r` 摘要，不變更候選、分類、警報框、數量或圖片。沒有可切換成自動刪除的開關；`exclude_suggestion` 只是研究建議。服務 `/api/5r/spatial-review` 明列 `mode=shadow_only`，政策SHA納入執行器識別。

以候選框外圍環帶尋找參照對應，擬合單一平移及線性明暗；候選本身與四周4px不參與擬合。16／32px兩範圍必須有一致位移、足夠相關性，且校正後沒有明顯殘留物件，才建議排除。穩定獨立小物件優先保護。參數在整批實驗前凍結，屬工程起始假設，未經獨立資料校準；本輪沒有為ng-129調低門檻。

本輪185張沒有建議排除，ng-129仍無足夠結構對應證據；**不可正式啟用自動排除**。保住79個人工位置不代表已驗證改善有效，因本輪建議數為0。完整結果與範圍見 `CHECKPOINT_5R_STRUCTURE_SHADOW_20261120.md`。

- `spatial5r.py`：外殼包絡、追加候選與小片段完整物件複核。
- `enclosure_guard5r.py`：避免新邊緣通道把固定結構的細長殘差升為警報；有真正螺絲核心的長候選仍可保留。
- `fragment_core_guard5r.py`：完整背景要否決原警報前，對可能是完整小物件的情況保守保留；縮放造成核心不穩定也不能直接誤刪。
- `enclosure_rescue5r.py`：穩定完整物件的受限補救；保存 `baseline-pre-rescue-*.json`、原排除證據、三種幾何範圍及兩次雙圖分數。新增警報同步更新統計與實際來源圖框。
- `spatial5r_runtime.py`：新流程的共用執行器，沿用原先已核對的模型與資料；快取識別包含新政策與執行器程式雜湊。
- `live5r_spatial_service.py`：獨立服務入口；不修改舊服務，也不更改舊套件的資格清單來繞過 SHA 核對。
- 每張結果保存 `baseline-5r-*.json`、`inspection_original.png`、`inspection_enclosure.png`，以及 `spatial5r`／`spatial_review5r` 決策證據。
- 除通過第7步補救的候選外，原排除結果不變；被救回的候選也保存原排除證據。所有保留及被排除的框都收錄於完整報告，框數不代表螺絲顆數。

## 啟動

先按 `START-HERE.md` 核對 Lean、參考圖、KPH33 及 5r 私人補充包。使用已核對且另行建立的隔離站台，不合併或覆寫舊站台。新入口預設使用 `workspace/5r-spatial-home`，不會自動從舊站台複製私人資料。

```powershell
$env:XRAY_5R_HOME = '新的已核對站台絕對路徑'
$env:XRAY_5R_PORT = '18771'
python experiments/dino/live5r_spatial_service.py
```

使用啟動訊息中的實際網址，進入 `/5r/batch`。`/api/5r/spatial-review` 顯示新政策與雜湊，`/api/5r/local-review` 保留既有圖庫核對資訊。圖庫切換後，舊調校試算不能直接套用，必須重新試算。

## 可重現驗證

`tools/run_spatial5r_regression.py` 接受外部私人清單，先核對每張原圖、參照及基線 SHA，再建立新的結果目錄。清單格式見工具說明；圖資與答案不放入 Git。

```text
python tools/run_spatial5r_regression.py --home NEW_HOME --manifest PRIVATE_PLAN.json --output NEW_OUTPUT --probe PASSED_PROBE.json --mode full
python tools/run_spatial5r_regression.py --home NEW_HOME --manifest PRIVATE_PLAN.json --output ANOTHER_NEW_OUTPUT --probe PASSED_PROBE.json --mode additive
python tools/test_spatial5r.py
```

`full` 從原始影像完整重跑；`additive` 對凍結的原偵測結果重新執行新增階段，不能稱為整個歷史資料集從頭重跑。工具完成不等於準確率驗收：仍要檢查全部新警報、實際螺絲位置、原有人工答案命中與完整報告。

本批 24 張的照片級指標必須與定位指標分開。NG 有警報不代表框到真正螺絲；零警報、對位警告也不能直接當成正常。未配對標註及未確認位置不得拿來調整規則或增加命中數。
