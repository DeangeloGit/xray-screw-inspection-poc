# 可攜式版本與軟排線誤判評估

日期：2026-11-01。分支：`codex/v2-portable-flex-cable`。
基準：`af6a5cd`，標籤 `checkpoint-2026-11-01-ui-manuals`。
儲存庫目前僅有此一提交；這是既有批次檢查成果的完整 checkpoint，而非單獨的第一版演算法。第一版保留於 detector_v1.py。

## 1. 可攜式執行檔

建議先使用 PyInstaller 的 onedir 模式：使用者複製整個發行資料夾，在相同作業系統及相容 CPU 的電腦雙擊啟動，不需另裝 Python。保留現有本機瀏覽器介面。先完成資料夾版，再考慮單檔版。

Windows EXE 必須在 Windows 建置；macOS 需獨立建置與驗證，不能將本機 macOS 產物當作 Windows 版本。目標 OS、CPU 與最低支援版本尚待確認。

程式碼檢查已找到以下必要改動：

- launch.py 目前以 `sys.executable app.py` 啟動；凍結後 sys.executable 是應用程式本身，需改為直接啟動服務或明確的服務子命令，避免遞迴啟動。
- detector.py 的 ROOT 同時代表程式資源及可寫資料。應分為封裝資源路徑，以及外部 data/outputs 工作路徑；不可把人工結果寫入單檔解壓暫存區。
- app.py 的 templates、static（含手冊）需明確打包並指定資源位置。
- library.analysis_key 目前雜湊 ROOT/detector.py；打包後通常沒有此原始檔，需改用建置時產生的演算法指紋。指紋應涵蓋會影響結果的程式與模型，不能每次啟動隨機改變。
- 正常參考 ok_0.png 為外部必要資料；目前未進 Git。發行包需有明確的參考圖配置及缺檔提示，不能假設新電腦已有本機 data。
- 保留本機監聽、就緒檢查與重複啟動處理，補上可讀的啟動失敗及唯讀資料夾提示。

驗收：在未安裝 Python 的乾淨目標電腦離線啟動；含中文、空白的路徑；正常圖缺失；上傳及批次；手冊靜態資源；人工判定保存與重啟恢復；複製整包後仍可使用；既有回歸驗證通過。現階段尚未產出或驗證執行檔。

官方依據：https://pyinstaller.org/en/stable/operating-mode.html

## 2. 誤判原因與方案選擇

目前為單張正常參考 + ORB/RANSAC 全機對齊 + 九區有限平移 + 高通差分。軟排線的局部彎曲不是整機剛性偏移；正常線材也會形成差分。現有 prioritize 已利用細長輪廓、正常深色結構與正負殘差降序，但不刪除候選；使用者仍逐一確認全部候選，所以只調排序不能解決複判負擔。

既有 v1_candidate_review.csv 在 ng_5、ng_9 中各記錄四個線材候選，屬暫定目視分類。這支持調查線材偏移，但不足以證明目前每張影像的誤報都來自軟排線。現有 20 張待測含重拍、僅一張正常參考，不能據此訓練並宣稱泛化改善。

| 方案 | 適合用途 | 主要限制 | 建議 |
| --- | --- | --- | --- |
| 多張正常參考、局部變異模型 | 容納正常線材位置變動 | 正常圖必須涵蓋真實裝配與拍攝變異，避免容忍掉小螺絲 | 優先建立比較基準 |
| 有界局部匹配與正負殘差配對 | 解釋線材移位產生的成對殘差 | 彎曲不一定成對；過強形變可把異物對齊掉 | 實驗性線材分數，保留原候選 |
| ResNet 候選分類 | 在差分後將局部候選分為螺絲、線材、固定結構、不確定 | 上游沒找到的螺絲仍會漏；需標註與獨立測試 | 優先 AI 試驗 |
| YOLO 螺絲偵測 | 直接在影像中定位螺絲，降低對參考差分的依賴 | 小物件、重疊、固定螺絲與游離螺絲區別都需專門資料 | 作為平行比較方案 |
| 線材分割 | 提供線材區域與上下文 | 線材上的螺絲可能被遮罩一起排除 | 不以線材遮罩直接判定正常 |

ResNet 是可用於分類的骨幹；此處建議以候選裁切圖做遷移學習，而非整張縮小分類。可比較只看待測局部，及同時看待測、正常參考、差分上下文的模型。需避免只學會固定座標與背景。

YOLO 的 detection 能輸出位置，segmentation 能輸出輪廓；本專案的建議是工程推論，不代表官方模型已能辨認這批 X-ray 螺絲。整張圖大幅縮小可能損失小螺絲，需比較保留細節的切片推論及跨片合併；區分固定結構也需上下文。

官方任務說明：https://docs.ultralytics.com/tasks/ 、https://docs.ultralytics.com/tasks/segment/
ResNet 分類模型依據：https://docs.pytorch.org/vision/master/models.html

## 3. 建議實作與驗證順序

1. 保留現有 checkpoint 與所有候選追溯，先完成可攜化路徑、啟動器及建置流程。
2. 蒐集多台正常機、不同線材位置與重拍；標註每張所有游離螺絲，以及線材、固定結構與不確定候選。納入螺絲在線材上、邊緣與遮蔽案例。
3. 以實體機台／配置／拍攝批次分組切分訓練、驗證與封存測試；同配置重拍及其裁切不可跨組。增強或合成影像只放訓練組，不能替代實拍測試。
4. 同組資料比較現行流程、多正常參考、候選 ResNet、直接 YOLO。AI 起初只提供分類與分數，保留不確定候選供人工確認。
5. 先在驗證組設定螺絲召回要求，再比較每張誤報數、每張需複判比例、複判時間及 CPU 耗時；最後在封存測試組評估。候選分類須同時報告上游候選召回與最終螺絲召回。
6. 以獨立缺陷實例數與漏檢案例呈現結果；少量資料零漏檢不等於已證明量產安全。是否自動省略候選／整張免複判，需另訂可接受漏檢率及驗收標準。

這次只建立分支與評估，未變更偵測行為、訓練模型或宣稱誤報已改善。
